Building a Desktop App in Rust: What I Learned

Why Rust?

I'd been putting off learning Rust for years. It always felt like something I should do, but never something I needed to do. Then I started building AssetHoard, a desktop app for managing game assets, and suddenly I had a reason.

The alternative was Electron. And look, Electron is fine. It works. But I've used enough Electron apps to know the feeling: the slight input lag, the 400MB memory footprint for what should be a simple tool, the fan spinning up when you open preferences.

I wanted something that felt native. Something fast. Something that wouldn't make my laptop sound like it was preparing for takeoff.

Rust promised speed without the footgun collection that comes with C++. Memory safety without a garbage collector. And honestly, I wanted to see what all the fuss was about.

The Stack

I went with Tauri for the UI layer. If you haven't come across it, Tauri lets you build desktop apps using web tech for the frontend (HTML, CSS, JavaScript) while writing the backend in Rust. It's like Electron's cooler, leaner cousin.

The selling point is size and performance. Where an Electron app might ship a 150MB binary and chew through RAM, a Tauri app can be under 10MB and sip memory politely.

But the real surprise was how seamless the IPC (inter-process communication) turned out to be. You define your Rust functions, expose them to the frontend with a macro, and call them from JavaScript like they're local. It just works. I expected way more friction.

#[tauri::command]
fn get_asset_count(state: State<AppState>) -> usize {
    state.assets.len()
}

Then from the frontend:

const count = await invoke('get_asset_count');

That's it. No serialisation headaches. No weird message passing. It felt almost too easy, which made me suspicious for weeks. But it held up.

What Was Harder Than Expected

3D Asset Parsing

AssetHoard previews 3D models. That means parsing FBX, glTF, OBJ, and a bunch of other formats. In JavaScript land, you'd grab three.js and call it a day. In Rust, you're stitching together crates that vary wildly in maturity and documentation.

Some formats had solid crates. Others had crates that technically worked but hadn't been updated since 2019. A few had no crates at all, which meant either writing a parser from scratch or calling out to C libraries via FFI.

The Rust ecosystem is incredible for some things. 3D asset parsing is not one of those things. Not yet, anyway.

Linux Support

I naively assumed that if it worked on macOS and Windows, Linux would be a quick port. It was not.

The issue wasn't the Rust code. It was everything else. Linux package management is a fractal of complexity. AppImage, Flatpak, Snap, deb, rpm, each with their own expectations about where libraries live and how dependencies get resolved.

And then there's the display server situation. X11 versus Wayland. Some distros default to one, some to the other, some let users switch between them. They handle things like clipboard access, window decorations, and keyboard input differently. Code that works perfectly on X11 might behave strangely on Wayland, or vice versa. It's a clusterfuck, frankly.

Tauri helps with some of this, but there's no escaping the underlying chaos. Getting consistent behaviour across Ubuntu, Fedora, and Arch, and across both display servers took way more time than I'd budgeted for.

What Was Surprisingly Good

The Compiler Is Your Mentor

Everyone says this, but it's true: the Rust compiler is annoyingly helpful. It catches mistakes that would've been runtime bugs in other languages. It suggests fixes. It explains why your code is wrong in terms you can actually understand.

The learning curve is steep at the start, but once you stop fighting the borrow checker and start listening to it, everything clicks. It's like having a very patient, very pedantic code reviewer built into your toolchain.

Performance Is Free (Almost)

I didn't have to think about performance much. I just wrote code that made sense, and it ran fast. No profiling rabbit holes. No caching layers to paper over slow abstractions.

When you're previewing thousands of assets, indexing files, and generating thumbnails, that headroom matters. AssetHoard feels snappy in a way that would've required serious optimisation work in a higher-level language.

Fearless Refactoring

This one surprised me. Because Rust is so strict about types and ownership, big refactors are way less scary. If it compiles, it probably works.

I've ripped out entire modules and restructured core data types without the creeping dread that usually accompanies that kind of change. The compiler tells you exactly what broke and where.

Would I Do It Again?

Yes. With caveats.

If you're building something performance-sensitive, something that needs to feel native, something you want to ship as a small, self-contained binary, Rust and Tauri are a genuinely great choice.

But if you're prototyping fast or building something UI-heavy with complex state management, you'll probably move quicker with TypeScript and Electron. The Rust ecosystem for GUI stuff is still maturing.

For AssetHoard, the tradeoffs made sense. The app needs to be fast. It needs to handle large file collections without choking. And I wanted users to actually enjoy opening it, not dread the memory spike.

What I'd Do Differently

Start with better error handling patterns earlier. I retrofitted proper error types and the thiserror crate after too much code was already written. That was painful.

I'd also spend more time upfront understanding the Linux packaging landscape. I treated it as a "figure it out later" problem and paid for that in crunch time before launch.

Final Thoughts

Rust has a reputation for being hard, and it is, at first. But the payoff is real. The code is fast, the binaries are small, and once you've internalised the ownership model, you write fewer bugs.

Tauri made the desktop app part surprisingly approachable. If you've been curious about Rust but couldn't justify learning it for backend or CLI work, building a desktop app might be the excuse you need.

AssetHoard is still in closed beta. If you're a game dev drowning in assets you can't find, sign up and give it a spin.
