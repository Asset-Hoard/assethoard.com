What is a .yymps file? GameMaker local packages

A .yymps file is a GameMaker local package: a zip archive holding a selection of resources, such as sprites, objects, scripts, sounds and tilesets, exported from one GameMaker project so they can be imported into another. If you have bought an asset pack for GameMaker on the Marketplace or itch.io, it probably arrived as a .yymps. This post covers what is inside one, how to import and create them, and how to see what a package contains without opening GameMaker.

What is inside a .yymps file?

A .yymps is an ordinary zip file with a GameMaker-specific extension. Open it and you will find:

  • Resource folders laid out the same way as a GameMaker project: sprites/, objects/, sounds/, scripts/, tilesets/, fonts/ and so on.
  • A .yy file for each resource. This is a JSON file describing the resource: a sprite's frames and playback speed, an object's sprite and parent, a sound's audio file and settings.
  • The raw files those resources use, such as the PNG frames of a sprite or the WAV and OGG files behind a sound.
  • A small metadata file describing the package itself.

The .yy files are what tie everything together. On its own, a sprite's .yy is just a list of frame references, and an object's .yy is mostly a pointer to a sprite. GameMaker reads them and rebuilds the resources when you import the package.

How to import a .yymps file into GameMaker

  1. Open the project you want to add the resources to.
  2. Choose Tools, Import Local Package from the menu.
  3. Select the .yymps file.
  4. GameMaker lists every resource in the package. Tick the ones you want and click Import.

The resources land in your Asset Browser like any others. If the package contains a resource with the same name as one already in your project, GameMaker will ask how to handle the clash, so read that dialog carefully before you click through.

How to create a .yymps file

To share resources between your own projects, or to distribute an asset pack:

  1. Open the project that holds the resources.
  2. Choose Tools, Create Local Package.
  3. Fill in the package details, then add the resources you want to include.
  4. Save the package. GameMaker writes a .yymps file you can import anywhere.

Include anything the resources depend on. If you export an object but not the sprite it uses, the object will import with a missing sprite.

.yymps vs .yyz vs .yy

GameMaker uses several similar extensions, and they are easy to mix up:

Extension What it is When you see it
.yymps A local package: chosen resources from a project, zipped Asset packs, Marketplace downloads, sharing resources between projects
.yyz A compressed export of a whole project Sharing or archiving an entire project
.yyp The project file, listing every resource in the project The root of every project folder
.yy A single resource's definition, in JSON One per sprite, object, sound and so on, inside a project or package
.yymp The older package format from GameMaker Studio 2 before version 2.3 Old asset packs

The short version: import a .yymps into a project, open a .yyz as a project.

How to open a .yymps file without GameMaker

Because a .yymps is a zip, any archive tool can open it. Use 7-Zip, or copy the file, rename the copy to .zip and open it in Windows Explorer or macOS Finder.

That shows you the files, but not much more. You will see folders of .yy JSON and PNG frames with names like spr_player_idle, and you have to open frames one at a time to work out what each sprite looks like. Sounds, tilesets and fonts are no easier. For a pack of a few hundred resources, that is a slow way to find the one you want.

Previewing .yymps packages in AssetHoard

AssetHoard reads .yymps packages and .yyz exports in place, without extracting them, and treats the resources inside like any other asset in your library:

  • Sprites play back as animations at their own playback speed.
  • Sounds play straight from the card.
  • Tilesets open with a grid overlay that respects offset and separation.
  • Fonts show their baked atlas.
  • Objects show the sprite they use.

Each resource is filed under the type it actually is, so a GameMaker sprite turns up alongside the rest of your sprites and the normal filters find it. Everything is searchable and taggable, which matters once you own more than a handful of packs. It works with the .yy format used since GameMaker Studio 2.3.
